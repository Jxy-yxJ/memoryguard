MemoryGuard

Bounded active memory maintenance for long-horizon embodied agents: detect stale object memories under environmental change, verify them with perception, refresh the stored state, and act on the refreshed memory — under a bounded verification budget.

The problem

Long-horizon agents store object memories so they do not have to search repeatedly. Those memories go stale when objects move. Acting on stale memory fails, but continuously re-verifying everything is wasteful — sensing and navigation are the expensive resources. This project studies a concrete question:

Under a limited sensing and navigation budget, which memories should an agent actively verify and maintain?

How it works

1Score

Rank memories by an expected-verification-value score from cheap pre-observation signals (revisit visibility, distance from the remembered pose, per-class visual-confusion indicator) and select the top-B under a budget. The score is deliberately simple and auditable; any learned P(stale) estimator can replace it.

2Verify

Navigate to the remembered pose with stepwise navigation and run an open-vocabulary detector (Grounding DINO + SAM 2) on the live RGB frame. The verifier decides stale/fresh and returns a detection-grounded candidate location. Oracle metadata is never a policy input.

3Update

When stale, the memory record is refreshed in place from detector evidence, recording the old position, the new position, the confidence, and the update source — so every mutation is traceable.

4Act

Navigate to the refreshed location and attempt the downstream action with honest interaction: forceAction=False, a yaw-corrected face-then-pick step, a camera-horizon sweep, and a bounded approach fallback over nearby reachable poses.

Auditability. Every experiment row records whether the verifier was used, the stale decision, whether memory was mutated, the measured revisit/task paths, TeleportFull flags, and a failure reason.

Supporting findings

  • Budgeted ranking cuts selected strict detector false negatives from 6 → 1 over budgets 1–6 on the FN-prone protocol; component ablation attributes the reduction to the visual-confusion prior (matched counterfactual: current 6, density-only 6, visual-only 0, combined 0).
  • Detection is not maintenance: a 32B vision-language model detects staleness in 6/6 single-call cases but chooses the correct update in only 3/6; a multi-round agent chain completes 0/6 full chains.
  • Verifier error characterization: all disagreements are false negatives (8/8) concentrated in same-type instance confusion, and targeted reruns show the slice is live-run sensitive rather than deterministic.

Evaluation protocol

Claims are tested with a paired design rather than aggregate success rates. Cases are pre-registered and passed through an outcome-free geometry screen (the stale location is at least 2 m from the true object and the refreshed location within 1.5 m, the target is pickupable, and same-type pairing is unambiguous). Active and passive arms then run the same frozen cases, same scene/seed/spawn, same stepwise navigation, and the same honest interaction; the passive arm acts from the stale location with no verifier and no memory mutation. We report exact counts, McNemar exact tests, and Clopper-Pearson intervals, and replicate on held-out scenes, target classes, and seeds.

Quickstart

git clone https://github.com/Jxy-yxJ/MemoryGuard.git
cd MemoryGuard
pip install -r requirements.txt          # AI2-THOR, numpy, pillow, matplotlib, opencv
python -m unittest discover -s tests     # 275 tests (CPU-only)

# screen a case universe, run both arms, analyze the pair
python -m embodied_memory_pilot.ai2thor_paired_hard_challenge_screen \
    --scene-targets FloorPlan2:Egg FloorPlan5:Bread --seeds 101 103 107 --k 4 \
    --freeze-mode round_robin --probe-mode rich --out-dir results/screen

python -m embodied_memory_pilot.ai2thor_live_gsam_closed_loop \
    --scenes FloorPlan2 FloorPlan5 --seeds 101 103 107 \
    --case-list results/screen/case_list_paired_hard_challenge_frozen_v1.json \
    --verification-budget 4 --revisit-mode stepwise --execute-task-bridge \
    --honest-interaction --max-alternate-poses 3 --rich-before-probe --out-dir results/active

python -m embodied_memory_pilot.ai2thor_paired_task_bridge_control \
    results/active/live_gsam_closed_loop.json --live-passive --honest-interaction --out-dir results/paired

python scripts/analyze_paired_hard_challenge.py \
    --active results/active/live_gsam_closed_loop.json \
    --paired results/paired/paired_task_bridge_control.json \
    --case-list results/screen/case_list_paired_hard_challenge_frozen_v1.json --out-dir results/analysis

# render a captioned demo video for a recorded case
python scripts/make_demo_video.py --row-source results/active/live_gsam_closed_loop.json \
    --case FloorPlan2:Potato:101 --mode active --out-dir videos

Scope and limitations

  • All results are AI2-THOR mechanism evidence on fixed, pre-registered case sets. The geometry screen conditions the evaluation; the passive baseline is expected to fail on screened cases, so the paired test establishes discrimination, not broad effectiveness.
  • Held-out replication uses a disclosed richer before-state probe than the original protocol.
  • No claim is made for ObjectNav/SPL, manipulation benchmarks, persistent writeback, cross-platform transfer, or real-robot performance.
